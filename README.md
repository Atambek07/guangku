# 🖋️ Графдзеркало — программный комплекс управления роботом-плоттером

Полное руководство по устройству, архитектуре, установке и эксплуатации комплекса для автоматического письма и черчения на бумаге/тетрадях (рабочая область ~21×30 см / A4, питание 12В 1А, подключение по USB-Serial с прошивкой GRBL).

> **Два режима работы:**  
> 💻 **Ноутбук как хост** — FastAPI-бэкенд + USB-порт плоттера, управление с телефона по локальной Wi-Fi.  
> 📱 **Телефон как хост** — Android-приложение со встроенным веб-сервером и USB-OTG, плоттер подключается напрямую к телефону.

## 1. Что такое Графдзеркало

Графдзеркало — это программно-аппаратный комплекс, который позволяет роботу-плоттеру автоматически писать конспекты на русском языке и наносить чертёжные рисунки на бумаге или в тетрадях. Основные сценарии:

### Приоритет №1 — рукописный конспект в тетрадь
Пользователь загружает или вставляет длинный текст на русском языке (десятки и сотни страниц). Система:
- сканирует папку `./fonts/` и находит пользовательские `.ttf`/`.otf` шрифты;
- проверяет поддержку кириллицы в каждом шрифте;
- переводит текст в векторные контуры (траектории пера) без разрывов и наложений по вине кодировок;
- размещает текст на выбранном носителе: клетка 5×5 мм, линейка, чистый лист или A4;
- учитывает поля, красную строку, межстрочный интервал, интервал между буквами и наклон шрифта;
- выполняет потоковую постраничную печать без ограничения по объёму документа.

### Приоритет №2 — архитектурные рисунки и чертежи на A4
Отдельный режим для загрузки векторных файлов (`.svg`), автоматического масштабирования под лист A4 (210×297 мм) с сохранением пропорций, настройки скорости черчения и подъёма/опускания пера.

### Управление со смартфона
Весь интерфейс на русском языке, адаптивный под экран смартфона и десктопа. Поскольку плоттер подключён по USB-Serial (GRBL), а управлять нужно со смартфона, реализована архитектура локального бэкенда:
- держит стабильное Serial-соединение с GRBL на хост-машине (Linux-ноутбук или одноплатник);
- отдаёт веб-интерфейс в браузер смартфона по локальной сети;
- делает предпросмотр страниц/траектории перед печатью;
- поддерживает потоковую отправку G-code с контролем кольцевого буфера GRBL;
- кнопки Старт / Пауза / Возобновить / Стоп / Домой (Homing/Zero), ручное перемещение осей X/Y, тест подъёма/опускания ручки.

## 2. Как устроено устройство (аппаратная часть)

### 2.1 Оси X и Y
Плоттер перемещает держатель с ручкой по двум осям:
- **X** — движение влево-вправо (по ширине листа, 210 мм);
- **Y** — движение вверх-вниз (по высоте листа, 297–300 мм).

Перемещение выполняется шаговыми двигателями через ременную или реечную передачу. Количество шагов на 1 мм зависит от конструкции (например, 80 шагов/мм) и задаётся в `config.yaml` (`steps_per_mm_x`, `steps_per_mm_y`).

### 2.2 Ось Z / перо
Третья ось (Z) отвечает за подъём и опускание ручки к бумаге и от неё:
- **Перо вниз** (`z_down_mm`) — стержень касается бумаги, идёт запись/черчение;
- **Перо вверх** (`z_up_mm`) — стержень приподнят над листом, совершается переезд между буквами, словами и штрихами без оставления следа.

Режим работы пера настраивается в секции `pen` конфига:
- `mode: z` — ось Z (G1 Z<pos>), типово для плоттеров с сервой на Z;
- `mode: servo` — сервопривод через M3 S<val>/M5;
- `mode: spindle` — шпиндель GRBL (M3/M5).

### 2.3 Питание 12В 1А
Плоттер питается от постоянного тока 12 Вольт, ток до 1 Ампера. Важно:
- использовать блок питания с выходом 12В и током не менее 1 А;
- при подключении нескольких шаговых двигателей и серво одновременно ток может приближаться к пределу — не перегружать источник;
- проверять полярность перед подключением.

### 2.4 USB-Serial и GRBL
Плоттер подключается к хост-компьютеру через USB-кабель. Внутри установлена прошивка **GRBL** (открытая прошивка для ЧПУ на Arduino-подобных контроллерах). GRBL:
- принимает G-команды через последовательный порт (Serial);
- управляет шаговыми двигателями и осью Z в реальном времени;
- имеет кольцевой incoming-буфер (~128 байт в GRBL v1.1), который можно переполнить, если слать команды слишком быстро;
- поддерживает поток управления в реальном времени: `!` (feed hold / пауза), `~` (resume / возобновление), `X` (сброс / жёсткая остановка), `?` (статус-отчёт), `$H` (homing), `$J` (jog / ручное перемещение).

### 2.5 Рабочая область A4 / 21×30 см
По умолчанию рабочая зона настроена на 210×300 мм (по ТЗ 21×30 см). Лист A4 — 210×297 мм, поэтому влезает с небольшим запасом по высоте. Начало координат (0,0) — левый верхний угол листа, ось Y направлена вниз по листу (натурально для разметки страницы).

## 3. Программная архитектура

Проект разделён на две независимые части, каждая из которых может быть «хостом» для плоттера.

### 3.1 Ноутбук как хост (`laptop/`)
Бэкенд на Python (FastAPI) запускается на Linux-ноутбуке или одноплатнике, к которому напрямую подключён плоттер по USB-Serial. Смартфон подключается к ноутбуку по Wi-Fi и управляет им через браузер.

```
Смартфон (браузер, Wi-Fi) ← HTTP/WebSocket → Python бэкенд (FastAPI, 0.0.0.0:8000)
                                                     |
                                             USB-Serial (GRBL) ←→ Плоттер (X, Y, Z/перо)
```

### 3.2 Телефон как хост (`phone/`)
Android-приложение со встроенным веб-сервером (NanoHTTPD, порт 8000) и библиотекой usb-serial-for-android. Плоттер подключается к телефону через USB-OTG переходник. Веб-интерфейс открывается внутри телефона по адресу `http://127.0.0.1:8000`.

```
Плоттер — USB-OTG — Телефон (Android-приложение + встроенный веб-сервер 8000) — браузер телефона
```

### 3.3 Схема взаимодействия (общая)
1. Пользователь вводит текст или загружает `.svg` через веб-интерфейс.
2. Бэкенд переводит текст/чертеж в последовательность штрихов (Stroke).
3. Генератор G-code создаёт файл `.nc` с командами для GRBL.
4. Потоковый стример отправляет G-code в GRBL с контролем кольцевого буфера (не более `max_inflight` команд без подтверждения `ok`).
5. Пользователь в реальном времени видит прогресс и может нажать Паузу, Стоп, Домой, Нуль.

## 5. Подробное описание модулей бэкенда (ноутбук)

Все файлы находятся в `laptop/backend/`.

### 5.1 `config.py` — конфигурация
Единственный источник аппаратных параметров. Загружается из `config.yaml` (если файл отсутствует — используются значения по умолчанию).

Ключевые секции:
- **serial** — порт (`/dev/ttyUSB0`, `/dev/ttyACM0`), baudrate (115200 по умолчанию для GRBL v1.1), таймауты, `max_inflight` (сколько команд можно отослать без подтверждения `ok`, по умолчанию 4), режим симуляции (`simulate: true` — работа без железа).
- **machine** — `steps_per_mm_x/y` (шагов двигателя на 1 мм), `work_width_mm` (210), `work_height_mm` (300), `origin_corner` (где ноль: top-left и др.), `y_inverted` (инверсия оси Y), `homing_enabled`, `zero_offset_x/y` (смещение нуля после G92/G10).
- **pen** — `mode` (z/servo/spindle), `z_down_mm` (положение перо пишет), `z_up_mm` (положение перо поднято), `z_feed` (скорость подъёма/опускания), шаблоны команд `pen_down_cmd` / `pen_up_cmd`.
- **feed** — `write` (скорость написания, мм/мин), `travel` (скорость перемещения перо поднято), `jog` (ручное перемещение), `z` (скорость оси Z).

### 5.2 `fonts.py` — сканирование шрифтов и проверка кириллицы
- Сканирует папку `./fonts/` на файлы `.ttf`, `.otf`, `.ttc`.
- Для каждого шрифта читает таблицу cmap через fontTools и подсчитывает количество кодпоинтов в диапазоне Cyrillic (U+0400–U+04FF).
- Проверяет контрольный набор букв `АБВГДЕЁЖЗИЙКЛМНОПРСТУФХЦЧШЩЪЫЬЭЮЯабвгдеёжзийклмнопрстуфхцчшщъыьэюя`.
- Возвращает процент покрытия кириллицы и список отсутствующих из образца букв. Это защищает от ситуации, когда пользователь подкладывает латинский шрифт и получает «кубики» вместо русского текста.

### 5.3 `glyphs.py` — перевод глифов TTF/OTF в полилинии
Алгоритм (контурный обвод, детерминированный и предсказуемый):
1. Берёт glyph по Unicode через cmap (кодировка обрабатывается fontTools корректно).
2. `RecordingPen` обходит контуры glyph: `moveTo`, `lineTo`, `curveTo` (кубическая Безье), `qCurveTo` (квадратичная TrueType), `closePath`.
3. Кривые сглаживаются в отрезки (flattening) с заданной точностью — перо идёт по кратким линейным сегментах, удобных для G-code.
4. Каждый замкнутый контур glyph = отдельный штрих: перо опускается на первой точке, ведётся по контуру, поднимается в конце. Переход между буквами/штрихами — перо поднято.
5. Применяются размер шрифта (мм), наклон (shear X от Y), интервал между буквами (tracking) и avance-width — курсор продвигается на ширину glyph + tracking.

Результат: список объектов `Stroke` (точки + флаг `pen_down`), готовых к генерации G-code.

### 5.4 `layout.py` — разметка страниц
Режимы разметки:
- **grid** — тетрадь в клетку (настраиваемый размер клетки, например 5×5 мм);
- **lined** — тетрадь в линейку (настраиваемый межстрочный интервал и поля);
- **blank** — чистый лист тетради/блокнота;
- **a4** — лист A4 (210×297 мм).

Функциональность:
- разбивка текста на абзацы по пустым строкам;
- перенос слов по ширине с учётом шрифта (жадный алгоритм);
- если слово не влезло — перенос по буквам;
- красная строка (отступ первой строки абзаца);
- поля (слева, справа, сверху, снизу);
- постраничная пагинация — когда вертикальный курсор достигает нижнего поля, создаётся новая страница;
- потоковая обработка любого объёма текста (десятки/сотни страниц) без падений по памяти;
- расчёт примерного времени печати на основе длины траектории и скорости подачи;
- генерация SVG-превью всех страниц для отображения в интерфейсе.

Координаты: мм, начало (0,0) — левый верхний угол листа, ось Y вниз.

### 5.5 `gcodegen.py` — генерация G-code
Принимает список `Page` или `Stroke` и формирует G-code:
- Заголовок: `G21` (мм), `G90` (абсолютные координаты), `G94` (подача в мм/мин), подъём перо, переход в ноль рабочей зоны.
- Для каждого штриха: если перо должно быть опущено — команда опускания перо (`pen_down_cmd`), затем `G1 X.. Y.. F<write>` по всем точкам контура; если перо поднято — команда подъёма перо (`pen_up_cmd`), затем `G0 X.. Y.. F<travel>` (быстрый переезд).
- Преобразование СК листа (X вправо, Y вниз) в СК станка с учётом `origin_corner`, `y_inverted`, `work_width_mm`, `work_height_mm`.
- Округление координат до 0.001 мм.
- Подвал: подъём перо, возврат в ноль, `M2` (конец программы).
- Сохранение в папку `gcode/`.

### 5.6 `svg_import.py` — импорт `.svg`
Минимальный парсер SVG-путей без внешних зависимостей:
- Поддерживает команды путей: `M`, `L`, `H`, `V`, `C`, `S`, `Q`, `T`, `Z` (в верхнем и нижнем регистре).
- Поддерживает элементы: `path`, `polyline`, `polygon`, `rect`, `circle`, `ellipse`, `line`.
- Кривые Безье сэмплируются в отрезки.
- Каждый контур = отдельный штрих `Stroke`.
- Координаты берутся как есть (мм); масштабирование под A4 выполняется на стороне вызова.

### 5.7 `serial_link.py` — потоковый GRBL-стример
Поддерживает соединение с GRBL по USB-Serial и управление станком.

Ключевые возможности:
- `connect()` — открытие COM-порта, пауза 2 сек на перезагрузку GRBL при открытии порта, запуск потока чтения ответов.
- `list_ports()` — список доступных последовательных портов через `pyserial.tools.list_ports`.
- `stream_gcode(gcode)` — постановка G-code на потоковую отправку. Команды делятся на строки, комментарии (`;`) и пустые строки отбрасываются. Отправка идёт с контролем `max_inflight`: не более N команд без подтверждения `ok` от GRBL, что предотвращает переполнение кольцевого буфера (~128 байт v1.1).
- `pause()` — команда `!` (feed hold, пауза).
- `resume()` — команда `~` (возобновление).
- `stop()` — команда `X` (жёсткая остановка / сброс GRBL), очистка очереди.
- `home()` — команда `$H` (homing, поиск нуля).
- `zero()` — команда `G92 X0 Y0` (установка текущей позиции как ноля).
- `jog(axis, mm, feed)` — команда `$J=G91 X.. Y.. F..` (ручное перемещение).
- `pen_down()` / `pen_up()` — тест опускания/подъёма перо.
- `simulate=True` — режим работы без железа (для отладки и разработки).

Потоки:
-_reader_loop_ — чтение ответов из Serial-порта, парсинг `ok`, `error`, `alarm`, статус-отчётов `<Idle|MPos:...|WPos:...|...>`.
- _pump_loop_ — отправка команд из очереди с соблюдением лимита незавершённых команд (`inflight < max_inflight`).

### 5.8 `jobs.py` — очередь задач печати
Отслеживание текущей задачи: ID, имя, G-code, статус (queued/running/paused/done/stopped/error), прогресс (строка/всего, процент), время создания/начала/окончания.

### 5.9 `preview.py` — рендер предпросмотра
Использует Pillow для отрисовки всех страниц в одно PNG-изображение:
- чёрный — штрих письма (перо вниз);
- серый — переезд перо поднято;
- пунктирная рамка — граница листа;
- подпись номера страницы.

### 5.10 `main.py` — FastAPI бэкенд
Точка входа. Эндпоинты:
- `GET /api/fonts` — список шрифтов с проверкой кириллицы;
- `GET /api/presets` — пресеты разметки;
- `POST /api/layout` — разметка текста на страницы (возвращает страницы, штрихи, SVG-превью, статистику);
- `POST /api/gcode` — генерация G-code из страниц;
- `POST /api/svg` — загрузка `.svg` → штрихи;
- `GET/POST /api/serial/...` — управление соединением, статусом, стримером, паузой, стопом, домой, нулём, жогом, тестом перо;
- `WebSocket /ws` — команды в реальном времени (`start`, `pause`, `resume`, `stop`, `home`, `zero`, `jog`, `pen_down`, `pen_up`, `connect`, `disconnect`, `get_status`) и рассылка статуса (`state`, `progress`, `message`, `line`, `total`).
- `GET /config.yaml` — отдача текущего конфига для просмотра в интерфейсе настроек.
- `GET /` — главная страница (веб-интерфейс).

Статика раздаётся из `laptop/static/`.

## 6. Алгоритмы работы

### 6.1 Перевод кириллического шрифта в траектории пера
1. Пользователь выбирает шрифт из `./fonts/`. Система проверяет его на поддержку кириллицы (cmap-таблица).
2. Текст разбивается на символы. Для каждого символа находится glyph через `font.getBestCmap()`.
3. `RecordingPen` обходит все контуры glyph. Каждый замкнутый контур превращается в список точек (полилинию).
4. Кривые Безье сглаживаются в отрезки (точность ~0.02 font units).
5. Каждый контур становится объектом `Stroke` с `pen_down=True`. Между контурами одной буквы и между буквами перо поднимается (G-code генератор добавляет команды подъёма/опускания).
6. Курсор продвигается на `advance-width + tracking` после каждого символа.
7. Применяется наклон шрифта (наклон по X пропорционально Y).
8. Пробелы обрабатываются как сдвиг курсора на ширину пробела + tracking.

### 6.2 Разметка страниц
1. Текст разбивается на абзацы по `\n\n` и на строки по `\n`.
2. Каждый абзац разбивается на слова.
3. Слова подбираются в строку по ширине с учётом размера шрифта, tracking и полей.
4. Первая строка абзаца получает отступ красной строки.
5. Вертикальный курсор перемещается на межстрочный интервал (или размер клетки) после каждой строки.
6. Если курсор достигает нижнего поля — новая страница.
7. Результат: список `Page`, каждая со списком `Stroke`. SVG-превью generating для всех страниц сразу.

### 6.3 Потоковая отправка G-code и кольцевой буфер GRBL
GRBL v1.1 имеет incoming-буфер около 128 байт. Если слать команды быстрее, чем станок их выполняет, буфер переполняется, порт забивается, и связь рвётся.

Алгоритм стримера:
1. Вся G-code программа разбивается на строки.
2. Строки ставятся в очередь `deque`.
3. Поток `pump_loop` отправляет команду, только если `inflight < max_inflight` (по умолчанию 4).
4. После отправки команда считается «в полёте» (`inflight++`), поток ждёт события `ok` от GRBL.
5. При получении `ok` — `inflight--`, событие сбрасывается, pump отправляет следующую команду.
6. Если `inflight` достиг `max_inflight`, поток блокируется до получения `ok`.
7. Это гарантирует, что буфер GRBL никогда не переполняется, и печать сотен страниц проходит стабильно.

## 7. Протокол GRBL — справочник команд

| Команда | Назначение | Примечание |
|---------|-----------|------------|
| `G21` | Единицы измерения в мм | Обязательно в заголовке |
| `G90` | Абсолютные координаты | Обязательно в заголовке |
| `G94` | Подача в мм/мин | Единицы длины в минуту |
| `G1 X.. Y.. F..` | Линейное перемещение со скоростью F | Используется для записи (перо вниз) |
| `G0 X.. Y.. F..` | Быстрое перемещение | Используется для переездов (перо вверх) |
| `G1 Z.. F..` | Движение оси Z (подъём/опускание перо) | `z_down_mm` / `z_up_mm` |
| `G92 X0 Y0` | Установка текущей позиции как ноля | Кнопка «Нуль» |
| `G10 L20 P1 X0 Y0` | Постоянное сохранение смещения нуля | Альтернатива G92 |
| `$H` | Homing (поиск нуля осей) | Кнопка «Домой», если прошивка поддерживает |
| `$J=G91 X10 F1500` | Jog — относительное ручное перемещение | Ручное управление X/Y |
| `!` | Feed hold (пауза) | Остановка выполнения, можно возобновить |
| `~` | Resume (возобновление) | Продолжить после паузы |
| `X` | Сброс / жёсткая остановка | Полная остановка, очистка очереди, требует повторного нуля |
| `?` | Статус-отчёт | Возвращает `<Idle|MPos:...|WPos:...|...>` |
| `ok` | Подтверждение команды | GRBL отвечает после выполнения каждой команды |
| `error` | Ошибка команды | Неверный G-команд или синтаксис |
| `alarm` | Авария GRBL | Требует разблокировки `$X` или сброса |

## 8. Установка и запуск

### 8.1 Ноутбук как хост (Linux)

#### Требования
- Linux (Ubuntu, Debian и аналоги) — ноутбук или одноплатник рядом с плоттером;
- Python 3.9+;
- Плоттер подключён к USB (`/dev/ttyUSB0` для CH340/CP2102, `/dev/ttyACM0` для Arduino-ориентированных);
- Права на последовательный порт: `sudo usermod -a -G dialout $USER` (после этого перелогиньтесь).

#### Пошаговая установка
```bash
# Перейдите в папку проекта
cd /home/atambek/projects/guangku/laptop

# Установите зависимости
bash scripts/install_deps.sh
# Либо вручную:
# pip install -r requirements.txt

# Положите свой рукописный шрифт (.ttf или .otf) в папку fonts/
# Пример: cp ~/Загрузки/MyHandwriting.ttf fonts/

# Отредактируйте config.yaml под ваш станок
nano config.yaml
# Укажите порт (например, /dev/ttyUSB0), скорость (115200),
# параметры осей, высоту перо (z_down_mm, z_up_mm) и скорости подачи.

# Запустите бэкенд
uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

Бэкенд будет доступен по адресу `http://0.0.0.0:8000` (со всех интерфейсов ноутбука).

#### Режим симуляции (без плоттера)
Если в `config.yaml` оставить `port:` пустым, бэкенд работает в режиме симуляции — можно отлаживать разметку и генерацию G-code без подключённого плоттера.

### 8.2 Телефон как хост (Android)

Если вы хотите, чтобы плоттер подключался **прямо к телефону** (без ноутбука):

1. Установите **Android Studio** с https://developer.android.com/studio.
2. Откройте в Android Studio папку `guangku/phone`.
3. Подключите телефон к компьютеру, включите на телефоне **Режим разработчика** и **Отладку по USB**.
4. Нажмите зелёную кнопку **Run (▶)** — приложение установится на телефон.
5. Подключите плоттер к телефону через **USB-OTG переходник**.
6. Откройте приложение, нажмите **«Подключить плоттер (USB)»**, дайте разрешение на доступ к USB.
7. Нажмите **«Открыть интерфейс (127.0.0.1:8000)»**.

Подробная инструкция для неподготовленного пользователя: `phone/INSTALL_PHONE_RU.md`.  
Обучение разработке Android с нуля: `phone/README_ANDROID.md`.

### 8.3 Подключение смартфона (к ноутбуку)
1. Ноутбук и телефон должны быть в одной Wi-Fi сети.
2. Узнайте IP ноутбука: `hostname -I` (например, `192.168.1.42`).
3. На телефоне откройте браузер: `http://192.168.1.42:8000`.
4. Если страница не открывается — проверьте брандмауэр (порт 8000 должен быть открыт) или временно отключите `ufw`/`firewalld` для проверки.

## 9. Руководство пользователя

### 9.1 Подготовка шрифтов
1. Положите свой рукописный `.ttf` (или `.otf`) шрифт в папку `laptop/fonts/` (для ноутбука) или скопируйте в `phone/app/src/main/assets/www/fonts/` (для телефона).
2. Запустите приложение. На вкладке «Настройки» или в интерфейсе конспекта шрифт появится в списке.
3. Система покажет: процент покрытия кириллицы, наличие образца букв (`АБВГДЕЁЖЗИЙКЛМНОПРСТУФХЦЧШЩЪЫЬЭЮЯабвгдеёжзийклмнопрстуфхцчшщъыьэюя`), список отсутствующих букв.
4. Если в списке отсутствуют нужные буквы (например, `Ъ` или `Ё`), текст с такими буквами будет пропущен (курсор сдвинется, но перо не рисует). Замените шрифт на более полный или добавьте недостающие глифы в редакторе шрифтов (FontForge, Glyphs).

### 9.2 Калибровка плоттера и ручки
Параметры в `config.yaml`, секция `pen`:

```yaml
pen:
  mode: z                 # z — ось Z (типично для плоттера с сервой на Z)
  z_down_mm: -1.5         # перо касается бумаги (пишет)
  z_up_mm: 3.0            # перо поднято над бумагой (переезд)
  z_feed: 600.0           # скорость опускания/подъёма, мм/мин
```

**Подбор экспериментально:**
1. Поднимите головку в ноль (X0 Y0), зафиксируйте ручку в держателе.
2. Нажмите кнопку **«Ручка вниз»** (команда `G1 Z{z_down}`).
3. Стержень должен чётко касаться бумаги, без провисания и без глубокого царапания.
4. Если ручка не пишет / плохо контактирует — уменьшите `z_down_mm` (опустите ниже, например `-2.0`…`-3.0`).
5. Если царапает бумагу или рвёт её — увеличьте `z_down_mm` (поднимите, например `-1.0`…`0`).
6. Если при подъёме перо мажет по бумаге — увеличьте `z_up_mm` (например `4`…`6 мм`) или скорость `z_feed`.
7. Угол прижима регулируется механически держателем: перо должно быть перпендикулярно листу, без перекоса.

### 9.3 Ноль рабочей зоны
Ноль (0,0) — левый верхний угол листа. Положите тетрадь/лист так, чтобы левый верхний угол совпадал с нулём станка. Прижмите лист скрепками или скотчом по краям.

В интерфейсе нажмите **«Нуль (G92)»** — команда `G92 X0 Y0` установит текущую позицию как начало координат. Проверьте, что головка сейчас над левым верхним углом листа.

### 9.4 Печать конспекта (пошагово)
1. Положите свой рукописный `.ttf` шрифт в `./fonts/`, перезапустите бэкенд.
2. Откройте `http://<IP-ноутбука>:8000`, вкладка **«Конспект (текст → тетрадь)»**.
3. Вставьте текст конспекта на русском (любого объёма — десятки и сотни страниц обрабатываются постранично, без лимита символов).
4. Выберите носитель (клетка 5×5 мм / линейка / чистый лист / A4) и шрифт.
5. Настройте размер шрифта, межстрочный интервал, интервал букв, поля, красную строку.
6. Нажмите **«Разместить страницы»** — появится предпросмотр всех страниц, количество страниц, примерно время печати.
7. Проверьте превью: текст попадает в клетки/между линий, нет наложений. При необходимости подправьте параметры и повторите разметку.
8. Нажмите **«Сформировать G-code»** — файл сохраняется в `gcode/`.
9. Подключите станок (вкладка Управление), нажмите **«Нуль»** (G92) в левом верхнем углу листа, опустите перо тестовой кнопкой.
10. Нажмите **«Отправить на станок»** — начнётся потоковая печать с контролем буфера. На экране — прогресс, кнопки Пауза / Возобновить / Стоп / Домой.
11. По окончании страницы смените лист/тетрадь, снова поставьте ноль и продолжите со следующей страницы.

### 9.5 Чертеж на листе A4 (пошагово)
1. Вкладка **«Чертеж A4 (SVG)»** — загрузите `.svg`-файл чертежа.
2. Нажмите **«Предпросмотр SVG»** — убедитесь, что чертеж масштабируется под A4 (210×297 мм) с сохранением пропорций.
3. Нажмите **«G-code из SVG»** — формируется G-code.
4. Положите лист A4, поставьте ноль в левом верхнем углу листа.
5. Нажмите **«Отправить на станок»**, настройте скорость черчения (в конфиге `feed.write` / `feed.travel`).

### 9.6 Управление со смартфона
Интерфейс полностью на русском, адаптивный под экран смартфона. Вкладка **«Управление станком»** содержит:
- выбор порта и скорости (baudrate);
- кнопки Подключить / Отключить;
- статусное поле с индикатором состояния (подключено / пауза / авария);
- кнопки Домой ($H), Нуль (G92), Пауза (!), Возобновить (~), Стоп (X);
- тест Ручка вниз / Ручка вверх;
- ручное перемещение осей X/Y с настраиваемым шагом (мм).

### Краткая структура Android-проекта (`phone/`)
```
app/src/main/
├── AndroidManifest.xml          # манифест (права USB, фильтр устройств, activity)
├── res/
│   ├── layout/activity_main.xml # экран приложения (кнопки, лог, статус)
│   ├── values/strings.xml       # строки на русском
│   ├── values/colors.xml        # цвета
│   ├── values/themes.xml        # тема оформления
│   └── xml/device_filter.xml    # фильтр USB-устройств для плоттера
├── java/com/guangku/plotter/
│   ├── MainActivity.kt          # главный экран + запуск веб-сервера
│   ├── UsbPlotter.kt            # связь с GRBL через USB-OTG (usb-serial-for-android)
│   └── WebServer.kt             # встроенный веб-сервер (NanoHTTPD, порт 8000)
└── assets/www/                  # копия веб-интерфейса (index.html, style.css, app.js)
```

### Основные классы
- **MainActivity.kt** — точка входа. Запускает `WebServer` на порту 8000, создаёт `UsbPlotter`, обрабатывает нажатия кнопок (Подключить / Отключить / Открыть интерфейс).
- **UsbPlotter.kt** — обёртка над библиотекой `usb-serial-for-android`. Находит USB-Seial устройство (CH340, CP2102, Arduino), открывает порт со скоростью 115200 baud, отправляет G-команды в GRBL, читает ответы (`ok`, `error`, `<Idle|...>`). Реализует очередь команд с контролем `max_inflight`.
- **WebServer.kt** — встроенный веб-сервер на базе NanoHTTPD. Слушает порт 8000, отдаёт HTML/JS/CSS из `assets/www/`, принимает запросы от браузера (`/api/serial/connect`, `/api/serial/stream`, `/api/serial/pause` и т.д.) и переводит их в вызовы `UsbPlotter`.

## 12. Устранение типовых ошибок

| Симптом | Причина | Что делать |
|---------|---------|------------|
| Ручка не пишет / плохой контакт | `z_down_mm` слишком мало (перо не касается бумаги) или засохший стержень | Уменьшите `z_down_mm` в config.yaml, проверьте стержень, прижмите держатель |
| Ручка машет / царапает бумагу | `z_down_mm` слишком много или перо не перпендикулярно | Увеличьте `z_down_mm`, отрегулируйте угол держателя |
| Пропускает буквы | Нет глифа в шрифте (неполная кириллица) | Проверьте вкладку Шрифты — отсутствующие буквы; замените шрифт |
| Поехал наклон / текст не по строкам | Лист лежит криво или неверно выставлен ноль | Ровно положите лист, проверьте параллельность клеток осям, переставьте ноль (G92) |
| Координаты сбились | Пропуск шагов, случайный сброс | Не трогайте головку во время печати; после сброса заново делайте Ноль (G92) |
| Не находится `/dev/ttyUSB0` или `/dev/ttyACM0` | Плоттер не подключен, другой порт, нет прав | Проверьте кабель, `ls /dev/ttyUSB* /dev/ttyACM*`, права dialout, выберите верный порт в интерфейсе |
| Обрыв связи / буфер GRBL переполнен | Слишком быстрая отправка без ожидания `ok` | Уменьшите `serial.max_inflight` в config.yaml (по умолчанию 4); используйте кнопку Стоп и перезапустите отправку |
| Пауза не работает / безопасная остановка | GRBL не в состоянии Hold | Нажмите Пауза (`!`), затем Возобновить (`~`) или Стоп (`X` — полный сброс). После Стопа заново ноль через G92 |
| Шрифты не отображаются в интерфейсе | Файл не .ttf/.otf, битый шрифт, не перезапущен бэкенд | Положите шрифт в `./fonts/`, проверьте через сканер, перезапустите uvicorn |
| Телефон не открывает `http://<IP>:8000` | Ноутбук и телефон не в одной Wi-Fi, брандмауэр блокирует порт 8000 | Проверьте сеть, откройте порт 8000 в брандмауэре (`ufw allow 8000/tcp`) |

### Аварийная остановка
Нажмите **«Стоп (X)** — GRBL сбрасывается, очередь команд очищается, перо поднимается. После этого обязательно переустановите ноль (`G92 X0 Y0` / кнопка **Нуль**) перед следующим запуском.

## 13. Примеры конфигурации

### `config.yaml` (ноутбук)
```yaml
serial:
  port: /dev/ttyUSB0      # или /dev/ttyACM0; пусто = режим симуляции
  baudrate: 115200        # GRBL v1.1 по умолчанию
  timeout: 2.0
  write_timeout: 2.0
  max_inflight: 4         # не более 4 команд без подтверждения 'ok'
  simulate: false

machine:
  steps_per_mm_x: 80.0    # шагов на 1 мм по X
  steps_per_mm_y: 80.0    # шагов на 1 мм по Y
  work_width_mm: 210.0    # ширина рабочей зоны (A4 = 210 мм)
  work_height_mm: 300.0   # высота рабочей зоны (по ТЗ 21×30 см)
  origin_corner: top-left # где ноль (0,0)
  y_inverted: true        # Y растёт вниз по листу
  homing_enabled: true
  zero_offset_x: 0.0
  zero_offset_y: 0.0

pen:
  mode: z                 # z | servo | spindle
  z_down_mm: -1.5         # перо пишет (касается бумаги)
  z_up_mm: 3.0            # перо поднято
  z_feed: 600.0           # скорость подъёма/опускания, мм/мин
  pen_down_cmd: "G1 Z{z_down} F{z_feed}"
  pen_up_cmd: "G1 Z{z_up} F{z_feed}"

feed:
  write: 800.0            # скорость написания, мм/мин
  travel: 2500.0          # скорость переезда перо поднято, мм/мин
  jog: 1500.0             # скорость ручного перемещения, мм/мин
  z: 600.0                # скорость оси Z, мм/мин

host: 0.0.0.0
port: 8000

default_font_size_mm: 8.0
default_line_height_mm: 14.0
default_tracking_mm: 1.0
default_word_spacing_mm: 2.5
default_slant_deg: 0.0
```

### Пример G-code (первый лист, клетка 5 мм)
```gcode
; конспект — сгенерировано плоттер-комплексом
; units: mm, absolute coordinates
G21          ; мм
G90          ; абсолютные координаты
G94          ; подача в мм/мин
G1 Z3.000 F600.0   ; перо поднято (старт)
G1 X0.000 Y0.000 F2500.0  ; в ноль рабочей зоны

G1 Z-1.5 F600.0    ; перо вниз
G1 X18.046 Y287.620 F800.0
G1 X18.193 Y287.637 F800.0
...
G1 Z3.0 F600.0     ; перо вверх
G1 X0.000 Y0.000 F2500.0  ; вернуть перо в ноль
M2                     ; конец программы
```
